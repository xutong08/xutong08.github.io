博客终于搭完咯 我搞懂了这些

发表于2026-10-04|更新于2026-10-04
|浏览量:

对着教程一步一步看,很多东西是真的不懂,但是好在最终搭成了,也通过搜索查询学习到了一些东西
有些东西好像懂了,又好像没有.所以我决定先把我觉得真正有用的那点东西记下来,免得以后全忘光

这些东西都是啥

大概:

我写的 md 文章 → Hexo 把它们变成网页 → 扔到 GitHub 上 → 别人就能访问了

  • Hexo：主角,吃进去 Markdown,吐出来网页
  • Node.js：Hexo 靠它运行,不装的话 hexo 命令根本用不了
  • Git / GitHub：Git 是往 GitHub 上传东西的工具,GitHub 白给你存网页,还能给你一个网址,叫 GitHub Pages
  • 主题：比如我用的 Butterfly,就是皮肤

安装

Node.js 官网下载个一路继续,Git 我电脑上好像本来就有（Mac 输 git --version 没报错就是有）这些教程里写的很清楚,似乎没什么好说的

提醒:先确认自己浏览器能打开 github.com,打不开的话后面全是各种超时,别问我怎么知道的

一些命令

装 hexo 命令行工具

-g 差不多是全局的意思,装一次以后哪个文件夹都能用

建一个空文件夹安装东西

这时候文件夹里就有博客了,可以开新博文

它会自己在 source/_posts/ 里建一个 md 文件,再往里面写字就行(我是用的VScode打开文件写,其他的还没研究)

写完之后的三连命令

cl = clean，g = generate，s = server

  • clean：把之前生成的东西清掉.为啥每次都要清呢因为不清的话有时候改了东西网页还是旧的(也不是很懂)
  • generate：重新生成网页
  • server：本地开一个服务器,浏览器开 localhost:4000 /127.0.0.1:4000自己先看一眼(在本地(如果有设备用的同一个网络,ip地址前三个数都一样,大概也算本地吧,也可以访问))

&& 就是 上一条跑完再跑下一条 ,可以少敲几次回车

提醒:这个服务器不能关,终端一关网页立马打不开,我一开始以为是网坏了……看完按 Ctrl + C 停掉

怎么传上网

本地看着没问题, s 换成 d

d = deploy,部署,也就是往 GitHub 上推.

但直接推是推不上去的,得先弄俩东西:

1. SSH 密钥

一路回车就ok,会生成两个文件:一个私钥自己藏好,一个 .pub 公钥.复制内容粘到 GitHub 的设置里（GitHub → Settings → SSH keys）

相当于给电脑配了个通行证,之后往 GitHub 推东西不用反复输密码,别人也冒充不了

2. 告诉 Hexo 往哪推

博客文件夹里的 _config.yml,最后改成这样:

repo 是仓库地址(注意这里要用 git@ 开头那个 SSH 地址,不然通行证用不上)

另外还要装一个插件,不然 hexo 会说它不会部署:

(哦对GitHub 上仓库名要老老实实起成 用户名.github.io,这样你的网址才是 https://用户名.github.io)

跑完 hexo d,等一会网址就能打开了

我踩的坑

  • 图片不要直接拖本地路径 贴进去,本地好好的,一传上网全裂了.图片直接放博客文件夹里
  • 配置文件缩进别乱按 _config.yml 里空格格数很重要,用 Tab 会出事
  • 页面没更新先 hexo cl 重来,可能是缓存还是啥搞得

最后

其实到现在我还是一知半解,比如 npm 是怎么把那么多包整下来的
不懂的以后慢慢折腾吧,要学习的东西太多了
